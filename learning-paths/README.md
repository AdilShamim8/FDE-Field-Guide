# Learning Paths

Six routes into FDE work, each written for a specific starting point. Every path covers the
same ground: what you already have, what you need to learn, what to skip, projects to build,
and an honest timeline.

- [Beginner to FDE](beginner-to-fde.md) - from little or no professional engineering experience
- [From Software Engineer](from-software-engineer.md) - the most common route; add customer work to production skills
- [From AI/ML Engineer](from-ai-ml-engineer.md) - add delivery, discovery, and ownership to model skills
- [From Data Engineer](from-data-engineer.md) - your skills map to the hardest 80% of deployments
- [From Solutions Engineer](from-solutions-engineer.md) - add production engineering depth to customer instincts
- [From Consultant](from-consultant.md) - add engineering ownership to engagement skills

## How to judge readiness

No path finishes on a date; it finishes when your evidence does. You are ready to apply for
FDE roles when you can point at a system you shipped into a production environment, a
requirement you turned from an ambiguous ask into a working deliverable, and a production
incident you debugged without hand-holding. The [portfolio section](../portfolio/README.md)
shows how to build that evidence deliberately.

A note on honesty: FDE hiring in 2025-2026 skews senior. An independent analysis of 146 FDE
postings found no titles targeting junior candidates
([job market overview](../job-market/01-market-overview.md)). Plan accordingly - the paths
assume you are building toward a first FDE role with real depth, not gaming a title change.
