# System Design

Architecture for FDE work: designing systems inside a customer's constraints, with
repeatable reference architectures, and decisions written down so they survive scrutiny.

- [Architecture for customer systems](01-architecture-for-customer-systems.md) - designing when you do not control the platform
- [Reference architectures](02-reference-architectures.md) - four repeatable architectures covering most engagements
- [Trade-offs and decision records](03-trade-offs-and-decision-records.md) - making decisions legible and reversible

System design in FDE work is less about scaling to a billion users and more about fitting
an existing organization. The best architecture is the one the customer's team can operate
after you leave.
