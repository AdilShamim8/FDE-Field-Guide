# ADR 001: local retrieval and exact quotation checks

This record documents a teaching implementation rather than a customer-approved production architecture. Initial record date: 2026-09-18. Implementation review: 2026-10-09.

## Status and context

Accepted for local reference development. Not accepted as evidence of production readiness or legal compliance. The example needs deterministic behavior without external model credentials, paid inference, or a backing database.

## Decision

Use feature-hashed vectors, hand-written word clusters, and token overlap to rank locally authored sample policies. Validate a quotation by exact text membership in the retrieved document section. In strict mode, absent verified evidence routes to review; P0 incidents still escalate.

This implementation is not BM25 or learned semantic embeddings. Exact membership verifies a local string relationship, not answer relevance, policy authority, factual completeness, or permission to disclose a document.

## Alternatives and trade-offs

- Pure token overlap offers a simpler baseline; compare it on independently labeled retrieval queries before claiming the hybrid is better.
- BM25 plus a learned embedding model adds external artifacts and runtime costs; adoption requires source licensing, model/version pinning, relevance labels, and measured improvement.
- External vector storage adds durability and scale but also operations and access-control boundaries. The current small corpus does not establish a need for it.

The chosen method is fast and inspectable locally but can rank unrelated text, gives no calibrated confidence, and encodes domain assumptions in word clusters. No measurements justify the former claimed 40–80 ms quote-verification overhead or a universal 100% precision guarantee; those claims are removed.

## Revisit conditions

Revisit when approved real policy documents and an untouched retrieval holdout exist, when workload measurements justify different storage, or when identity and access policy require stronger boundaries. Record both quality and operational costs on the same workload. Keep prior known cases as regression data.
